# Kanboard — Business Logic & Domain Rules

This document outlines the strict business constraints and domain logic rules enforced by the backend and database.

---

## 🔐 Role-Based Access Control (RBAC) Rules

Every board member is assigned a specific role (`owner`, `admin`, or `member`). The table below outlines what actions each role is allowed to perform.

| Feature / Action | Owner | Admin | Member |
| :--- | :---: | :---: | :---: |
| **Delete Board** | ✅ | ❌ | ❌ |
| **Transfer Ownership** | ✅ | ❌ | ❌ |
| **Rename / Recolor Board** | ✅ | ✅ | ❌ |
| **Invite New Members** | ✅ | ✅ | ❌ |
| **Remove Members (Self)** | ✅ (Must transfer ownership first) | ✅ | ✅ |
| **Remove Other Members** | ✅ | ✅ (Cannot remove owner) | ❌ |
| **Change Member Roles** | ✅ | ✅ (Cannot change owner) | ❌ |
| **Create / Delete Columns** | ✅ | ✅ | ❌ |
| **Rename Columns** | ✅ | ✅ | ❌ |
| **Reorder Columns** | ✅ | ✅ | ❌ |
| **Create / Delete Tasks** | ✅ | ✅ | ✅ |
| **Edit Task Content / Assign** | ✅ | ✅ | ✅ |
| **Move Tasks (Drag & Drop)** | ✅ | ✅ | ✅ |
| **Use Gemini AI Functions** | ✅ | ✅ | ✅ |

## 📐 Data Integrity & Validation Rules

### 1. Board & Column Constraints
*   A board must have at least one owner. The owner's membership row cannot be deleted unless another member is promoted to owner first.
*   Column names must be unique within the same board (case-insensitive). You cannot have two columns named "Todo" on the same board.
*   Positions of columns and tasks are computed as double-precision floating-point numbers. If the position gap between two items becomes smaller than `1e-9`, the backend automatically triggers a re-spacing transaction to reset positions to intervals of `1000`.

### 2. Task Assignment Constraints
*   A task can only be assigned to a user who is an active member of the task's parent board. The assignee selection dropdown is filtered on the backend.
*   If a board member is removed from a board, any tasks assigned to them on that board are set to `assignee_id = NULL` (enforced via database constraints and services).

### 3. AI Safety & Rate Limits
*   Gemini AI requests are subject to strict rate limits to prevent cost inflation:
    *   Max **15 requests per minute** per user.
    *   Tasks generated by the AI must not exceed a maximum count of **15 tasks** per request.
    *   Task descriptions generated by the breakdown service are limited to **500 characters** to conserve token usage.
